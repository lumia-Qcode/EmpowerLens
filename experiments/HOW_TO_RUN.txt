THE SHORT VERSION: open the notebook on Kaggle, run the cells top to bottom.
Every command below is already inside a cell — you do not type them. They are
listed so you know what you are looking at.


WHO RUNS WHAT
=============
The work splits into two tracks that can run in parallel, on two Kaggle
accounts, at the same time.

  TRACK A — IZZA        the notebook, Experiments 1-6 and 8
  TRACK B — NAYAB       Experiment 7 only (flat vs cascade), by hand

They do not depend on each other and can be done in either order.

WHY E7 IS SPLIT OUT AND RUN BY ONE PERSON
-----------------------------------------
E7 compares flat against cascade, and that gap is tiny — the previous
(confounded) comparison gave +0.003.

--deterministic makes a re-run reproduce EXACTLY on the SAME machine. It does
NOT make two different GPUs agree: a T4 and a P100 pick different kernels and
different mixed-precision paths, and Kaggle hands out both. So if one person ran
flat and another ran cascade, architecture and hardware would vary together and a
0.003 difference could not be attributed to either.

Therefore BOTH E7 arms — flat AND cascade — are run by one person, in one
session, on one GPU. Track A also produces a flat multilabel number (E6); treat
that as a REPLICATION CHECK of Track B's flat arm, not as its comparator. If the
two land close, that is reassuring. If they diverge, that divergence is itself
worth reporting as cross-machine variance.


TRACK A — IZZA: the notebook (sections 0-11)
---------------------------------------------
Order is fixed. Sections 1-2 are gates; 3-4 are cheap audits that decide what is
worth running afterwards.

   SESSION 1  (~4 hr)
     0.  Setup — clone + install. RUN ONCE, it starts with rm -rf.
     1.  Preflight — must report 0 leaked rows.
     2.  Determinism — must say PASS.
     3.  E1 pass 1 — data audit. Decides whether E3/E4/E5 are worth GPU time.
     4.  E8 — truncation. Confirms 512 tokens.
     5.  E6 — multilabel + thresholds.        3 runs, ~40 min
     6.  E1 pass 2 — per-class + confusion, using E6's checkpoints.
     7.  E2 — dataset ablation, 5 arms.      15 runs, ~3 hr
     11. Zip.  <-- DO THIS BEFORE THE SESSION ENDS

   SESSION 2  (~4 hr)
     0.  Setup again (new session = new clone).
     8.  E3 -> E4 -> E5, in that order.      21 runs, ~4 hr
         Set BEST_LOSS in the E5 cell from the E3/E4 tables.
     10. Comparable table.
     11. Zip.

   Skip section 9 — that is Track B's, and the cell only prints the protocol.
   Skip section 8 entirely if E1 showed the imbalance is mild.


TRACK B — NAYAB: Experiment 7 (docs/E7_PROTOCOL.md)
----------------------------------------------------
Not in the notebook. Run these by hand in Kaggle cells, prefixed with `!`.
ALL OF IT IN ONE SESSION, ON ONE GPU.

   ONE SESSION  (~2-2.5 hr)
     1. Clone the repo, same as the notebook's cell 0.
     2. Print and record the provenance:
            gpu, torch version, transformers version, commit hash
     3. Verify determinism:
            python -m src.determinism --check          -> must say PASS
     4. Regenerate the Stage 2 splits from the CLEAN source:
            python -m src.make_splits_cascade
                --source data/splits --out data/splits_stage2_annotated
            python -m src.make_splits_clean --check
                --source data/splits_stage2_annotated --dest /tmp/x
        (one line each — wrapped here for readability)
        The second must report 0 leaked rows. The shipped data/splits_stage2
        came from the leaked combined dir — do not use it.
     5. For each seed in 42, 1337, 2024:
            a. train Stage 1 (binary, full splits)
            b. train Stage 2 (multilabel, distorted-only splits)
            c. train flat  (multilabel, full splits)   <-- the comparator
            d. evaluate the cascade end to end
        9 training runs plus 3 cascade evaluations.
     6. Zip and download.

   Exact commands: docs/E7_PROTOCOL.md
   Step 5c is NOT optional. It is the comparator, and Track A's copy of it was
   produced on different hardware.


MERGING THE TWO TRACKS
----------------------
Both write into results_rerun/ using the same naming, so unzip Track B's output
over Track A's and the section 10 table picks up everything.

Two numbers from different tracks are comparable if they are both on the
yardstick exam, same task, leaked = False, and post-determinism — the same rule
as everywhere else. The ONE comparison that must stay within a single track is
flat-vs-cascade, for the hardware reason above.


WHY THIS REPLACED THE PREVIOUS SUITE
------------------------------------
Measured on the data in this repo, not estimated:

1. THE TRAINING DATA CONTAINED THE TEST SET.
   data/splits_combined/train.csv holds 396 rows whose text also appears in the
   Annotated val/test — 195 of the 253 test rows, 77% of the test set. Every
   Experiment 3-8 cell in the old notebook pointed at --splits
   data/splits_combined, so all of those numbers came from models that had
   already seen three-quarters of their own exam.

   Worse: on those 195 shared texts the two corpora agree on the label only 36%
   of the time, so the model mostly saw the test passage with the WRONG answer
   attached. The numbers are wrong by an unknown amount in an unknown direction.

2. DUPLICATE ROWS RE-WEIGHTED TRAINING.
   4,645 train rows, only 3,019 unique texts — 1,626 duplicates.

3. EVERY EXPERIMENT SAT A DIFFERENT EXAM.
   E2 scored each corpus on its own test set, E3-E8 on Combined, Month-1 on
   Annotated. A higher number in one says nothing about another.

4. RUNS DID NOT REPRODUCE.
   E6 and E7 were the same configuration and disagreed by 0.047 macro-F1 at seed
   42, while reporting a seed-to-seed SD of 0.007. Run-to-run noise was seven
   times the published error bar.

5. E1's MODEL HALF NEVER RAN.
   --checkpoint-mc / --checkpoint-ml were commented out, so no per-class
   precision/recall/F1 and no confusion matrices were ever produced.

6. NOBODY VALIDATED THE EPOCH BUDGET.
   --epochs 4 was a default nobody tested, and no run saved a per-epoch curve,
   so it could not even be checked afterwards.


STEP 0 — PREREQUISITES
----------------------
The script lives at experiments/experiments_flat_mentalroberta.py and runs as
   python -m experiments.experiments_flat_mentalroberta
The duplicate copy that used to sit in src/ has been deleted; there is one file.

Branch: nayab-space.  The notebook clones it in its first cell.

These frozen split dirs must be committed (they are):

   data/splits_codipas_transfer_matched/ CODIPAS, 2,024 rows, Annotated test set

These are BUILT BY THE NOTEBOOK, do not commit them by hand:

   data/splits_combined_clean/           leak removed

STEP 1 — KAGGLE SETUP
---------------------
Settings -> Accelerator: GPU T4.  Internet: On.

Run the first cell ONCE per session. It starts with `rm -rf`, so re-running it
deletes every result and checkpoint trained so far. If you need to restart,
begin from the second cell.

The notebook sets CUDA_VISIBLE_DEVICES=0. Kaggle's "T4 x2" deadlocks this stack
across devices, and it hangs rather than erroring.


STEP 2 — THE TWO GATES (sections 1-2, under a minute)
-----------------------------------------------------
Nothing below is trustworthy until both pass.

  Section 1  Preflight. Rebuilds the derived split dirs with the contamination
             removed, then re-audits its own output and fails if any leak
             survives. Also builds the volume-matched arms.

                 python -m src.make_splits_clean --force
                 python -m src.make_splits_clean --check

             Expected: splits_*_clean and splits_combined_matched all show
             0 leaked rows. The pre-fix dirs still show 396 — that is correct,
             they are kept unedited and nothing trains on them.

  Section 2  Determinism. Trains a tiny model twice at the same seed and checks
             the results are bit-identical.

                 python -m src.determinism --check

             Expected: "PASS - bit-identical."

             If it says FAIL, stop. Every +/- SD from this machine would be
             meaningless. warn_only=True means an op with no deterministic
             kernel warns instead of crashing, which is exactly why this check
             is not optional — it turns "determinism requested" into
             "determinism demonstrated".


STEP 3 — THE AUDIT GATES (sections 3-4, ~2 minutes, no GPU)
------------------------------------------------------------
  Section 3  E1 pass 1 — class frequencies, per-label prevalence split by
             train/val/test, and label co-occurrence (counts + Jaccard).
             THIS DECIDES whether E3/E4/E5 are worth GPU time at all.

  Section 4  E8 — median, p90, p95 token length and percent truncated at 128 /
             256 / 512. Confirms 512 is the right budget. This is what exposed
             the previous suite's worst configuration error: the cascade ran at
             256 where 24.9% of test rows truncate, against 2.4% at 512.


STEP 4 — THE TRAINING RUNS
--------------------------
Protocol, identical everywhere (set once in the Section 0 config cell):

   model        mental/mental-roberta-base
   epochs       8      (4 was never validated; every run now saves its curve)
   max_length   512    (2.4% truncation vs 24.9% at 256)
   batch_size   16
   lr           2e-5
   seeds        42, 1337, 2024
   determinism  on

  Section 5  E6 — multilabel per-label + thresholds.        3 runs, ~40 min
             Thresholds are swept on VAL only, then frozen for test.
             Run this before E2: it produces the checkpoints E1 pass 2 needs.
             It also prints, per run, "best epoch N of 8". If the peak is
             consistently 8 of 8, the budget is still too small and everything
             is under-trained — raise EPOCHS and re-run.

  Section 6  E1 pass 2 — per-class precision/recall/F1 and confusion matrices,
             using E6's checkpoints. This is the half that never ran before.
             Confusion matrices exist for binary and multiclass only; multilabel
             has no single predicted class per row to cross-tabulate.

  Section 7  E2 — dataset ablation, FIVE arms.             15 runs, ~3 hr

                arm                 train rows   labels
                annotated_only          2,024    human
                codipas_clean           2,224    rule
                codipas_matched         2,024    rule
                combined_clean          2,623    mixed
                combined_matched        2,024    mixed

             The two matched arms are what make this answerable:
                annotated_only vs combined_matched -> LABEL CONVENTION,
                                                      volume held fixed
                combined_matched vs combined_clean -> VOLUME,
                                                      convention held fixed

             Every arm is scored on BOTH its own test set (home) and always
             data/splits/test.csv (yardstick). Only yardstick numbers are
             comparable across experiments.

             Expected result: merging HURTS the fine-grained task. The two label
             sets agree at Cohen's kappa 0.199 on the 11-class question (36.8%
             raw), and among rows both call distorted they disagree about which
             one 73% of the time. A clear negative result on a fixed test set is
             a real finding, and more defensible than a marginal win.

  Section 8  E3 -> E4 -> E5, IN ORDER.                     21 runs, ~4 hr
             Each reads the previous winner. E4 is only worth running if E3's
             weighted CE did not close the gap; E5 pairs sampling with whichever
             loss won. Set BEST_LOSS in the E5 cell from the E3/E4 tables.

             All three train on Annotated (previously they pointed at the leaked
             combined dir), so home == yardstick and they compare directly to
             each other, to E6, and to the Month-1 baselines.

             SKIP THIS WHOLE SECTION if E1 showed the imbalance is mild.


STEP 5 — EXPERIMENT 7 (separate, see docs/E7_PROTOCOL.md)
----------------------------------------------------------
Section 9 does not train anything; it prints the protocol.

Both arms — flat AND cascade — are run by one person so they share one
configuration. The previous comparison was not valid because the cascade ran at
max_length 256 (24.9% truncation) against the flat side's 512 (2.4%), and
because data/splits_stage2 was derived from the leaked combined dir.

Before running E7, regenerate the Stage 2 splits from the clean source:

   python -m src.make_splits_cascade --source data/splits \
       --out data/splits_stage2_annotated
   python -m src.make_splits_clean --check \
       --source data/splits_stage2_annotated --dest /tmp/x

The second must report 0 leaked rows.

Report three numbers SEPARATELY:
   1. Stage 1 (binary)                positive_class_f1
   2. Stage 2 (multilabel, isolated)  macro_f1 on distorted-only rows
   3. End-to-end                      macro_f1, Stage 1 gating Stage 2

Number 2 IS NOT A CASCADE RESULT and must never be quoted as one — it is
measured only on rows already known to be distorted, so it hides every Stage 1
false negative. src/evaluate.py refuses distorted-only splits without an
explicit --allow-distorted-only flag to stop exactly that mistake.


STEP 6 — COLLECT (sections 10-11)
---------------------------------
  Section 10  Rolls every two_exams.csv into one table and applies the
              comparability rule. Rows failing it are shown separately rather
              than silently mixed in.

  Section 11  Copies results into /kaggle/working and zips them.
              RUN THIS BEFORE THE SESSION ENDS. Kaggle reclaims the working
              directory on teardown; anything not copied out is gone.


TIME AND SESSION PLANNING
-------------------------
39 training runs total. At roughly 12-14 min per run on a T4 that is about
8-9 hours — over Kaggle's 9-hour session cap, so plan two sessions:

   Session 1   sections 1-7  (preflight -> E2)          ~4 hr, then zip
   Session 2   section 8, then 10-11                    ~4 hr, then zip

Results accumulate in results_rerun/ across sessions, so splitting is fine.

THIS IS AN ESTIMATE, NOT MEASURED. Time your first E6 run and scale from it.

If short on GPU time, cut in this order:
   1. E4 and E5 (15 runs) — both are conditional on E3's outcome
   2. Drop to 1 seed for a first pass, then 3 seeds on whatever looks worth
      reporting. Nothing single-seed goes in the write-up.
Do NOT cut E6 (it produces the checkpoints E1 pass 2 needs) or E2's first three
arms (that is the experiment with an actual finding in it).


WHAT YOU CAN AND CANNOT CLAIM
-----------------------------
Two numbers may sit in the same column only if ALL FOUR hold:
   1. from the YARDSTICK exam (data/splits/test.csv, the same 253 rows)
   2. on the SAME TASK (2, 11 and 10 classes are three different exams)
   3. marked leaked = False
   4. produced AFTER the determinism check passed

All four are recorded per row in all_runs_two_exams.csv, so this is checkable
rather than remembered.

NOT comparable, by design:
   - home-exam scores from different corpora
   - zero-shot vs calibrated yardstick numbers (different questions)
   - val against test
   - anything in results_experiments/ or results_combined/, which came from the
     contaminated splits

METRICS
   Headline is macro-F1: it averages the ten labels equally, so a class the
   model never predicts drags it down. Micro-F1 pools all labels into one count
   and lets the frequent ones dominate — a model that perfectly predicts the 3
   commonest labels and ignores the other 7 scores micro 0.582, macro 0.300 on
   this val set.

   Multiclass selects on macro_f1_10 (the ten distortions, no_distortion
   dropped). Plain macro_f1 there includes no_distortion, which is 36.9% of rows
   and by far the easiest class.

   roc_auc is a DIAGNOSTIC, never a headline. F1 cannot tell "has not learned
   the class" apart from "ranks it correctly but the threshold is wrong" — those
   need opposite fixes. A low F1 beside a high AUC localises the fault to
   calibration.

   Accuracy is never a headline anywhere in this project.


TROUBLESHOOTING
---------------
"No module named src"
    You are not in the repo directory. Re-run the clone cell (which does
    %cd empowerlens), or %cd into it manually.

"experiments/experiments_flat_mentalroberta.py not found"
    Wrong branch. The notebook clones nayab-space.

Preflight reports a leak in a *_clean dir
    Should be impossible — the builder re-audits itself and raises. If you see
    it, the source dirs changed; regenerate with --force and report it.

Determinism check says FAIL
    Stop. Do not quote any +/- SD from that machine. Check that
    CUBLAS_WORKSPACE_CONFIG=:4096:8 is set before torch is imported.

A run peaked at "best epoch 8 of 8"
    The epoch budget is too small and that run is under-trained. Raise EPOCHS.

Session died mid-run
    Results already written to results_rerun/ survive only if you zipped them.
    Otherwise re-run from the last completed section — the notebook is
    section-by-section restartable, apart from the clone cell.
